# Children Park VLM

멀티모달 대규모 언어모델을 활용한 사용자 관점의 어린이공원 평가

```
최근수정일: 26. 10. 30.
작성자: 인하대학교 공간정보공학과 도시공간연구실 이태수
연구 관련 문의: dosiri24@inha.edu
```

## 연구 개요

멀티모달 대규모 언어모델(MLLM)에 어린이 페르소나를 부여해 인천 미추홀구 어린이공원 53곳을 평가하는 연구입니다. 어린이공원은 기부채납 등으로 비슷한 형태와 배치로 공급되는 경우가 많고, 계획과 평가도 연구자의 현장조사나 보호자 설문처럼 성인의 시선으로 이루어집니다. 어린이에게 직접 묻기에는 공원 수가 많고 보호자 동의와 윤리 심사의 부담도 큽니다. 최근 MLLM에 도시환경 사진을 보여 주고 평가하게 하는 연구가 늘고 있는데, 대부분 모델에 아무 관점도 주지 않고 평가하게 합니다. 페르소나가 없는 모델의 답은 중립보다 중년 남성의 응답에 가깝다는 보고도 있어, 이 연구에서는 **어린이 페르소나**를 주었을 때 **페르소나 없음**과 무엇이 달라지는지 비교합니다. 계획 과정에서 빠지기 쉬운 사용자 관점을 보완하는 보조도구로 MLLM을 쓸 수 있을지 보려 합니다. 이에 따라 제가 정의한 연구 질문은 아래와 같습니다.

### 연구 질문

1. 어린이 페르소나를 부여한 MLLM은 페르소나 없음과 비교해 어린이공원을 다르게 평가하는가?
2. 어린이 페르소나를 부여한 MLLM은 연령과 성별 조합에 따라 어린이공원을 다르게 평가하는가?

## 실험 설계

| 조건 | 페르소나 | 가설 |
|------|----------|------|
| 페르소나 없음 | 없음 (선행연구 방식) | 비교 기준 |
| 어린이 페르소나 6개 | 만 6·9·12세 × 남·여 | H1, H2 |

**규모**: 1,855회 호출 (53곳 × 7조건 × 5회), 점수 14,840개 (8개 평가요소)

연령은 어린이 놀이 성향을 다룬 선행연구를 참고해 정하였습니다. 놀이 성향의 양 끝인 6세와 12세를 두고, 선호하는 놀이시설이 바뀌는 시기라는 9세를 그 사이에 넣었습니다. 같은 사진이어도 모델의 답은 호출마다 조금씩 달라지기 때문에, 공원과 조건마다 5번씩 독립적으로 호출하고 그 평균을 공원의 점수로 썼습니다.

## 연구의 특징

이 연구에서 제가 중요하게 보는 포인트는 **관점 하나만 바꾸고 나머지는 모두 고정**했다는 점입니다. 일곱 조건은 같은 사진, 같은 시스템 지시, 같은 평가 기준을 쓰고, 어린이 조건에만 "당신은 만 6세 남자 어린이입니다" 같은 한 문장이 더해집니다. 이렇게 하면 조건 간 점수 차이를 페르소나 한 줄에서 나온 차이로 볼 수 있다고 생각했습니다.

저는 점수만큼 **근거 텍스트**도 중요하게 봤습니다. 모델이 평가요소마다 사진에서 본 내용을 먼저 쓰고 그 근거에 맞는 점수를 정하게 하였는데, 이를 통하여 점수가 페르소나에 일과되게 부여되는 것을 기대할 수 있습니다.

## 사진 자료 구축

공원 경계의 무게중심을 기준으로 정동, 정서, 정남, 정북 경계 지점에서 중심을 향해 연구자가 직접 촬영했습니다. 렌즈 높이는 어린이 눈높이인 110cm로 고정했고, 해가 드는 가을에 같은 카메라로 촬영했습니다. 공원마다 사진은 4장, 총 53개소에 대하여 212장입니다. 

## 프롬프트 설계

### 1. 근거 선작성 후 점수 부여

평가요소마다 사진에서 확인할 수 있는 내용을 2~3문장으로 먼저 쓰고, 그 근거에 맞는 점수를 1~4점 중에서 고르게 했습니다. 점수가 사진 속 단서에서 나오게 하려 했습니다. 척도는 중간값이 없는 4점으로 두어, 모델이 중립으로 몰리는 경향을 줄이려 하였습니다.

### 2. 촬영 방향 표기

근거 문장마다 그 단서가 보인 사진의 촬영 방향을 괄호로 인용하게 하였는데, 이는 모델이 네 장을 고르게 보는지 확인하려는 장치입니다. 실제로 분석을 진행해 보니 동서남북 인용 비율이 23~27%로 고르게 나왔습니다.

### 3. 페르소나 최소화

어린이 페르소나는 "당신은 만 N세 남자(여자) 어린이입니다. 당신의 관점에서 평가하세요." 한 문장입니다. 키나 성격 등의 구체적인 페르소나 를 부여하면 보다 어린이 같은 모습일 수 있으나, 이것이 연구자가 주입하는 어린이 라는 것에 대한 편향일 수 있다는 점을 유의해야 합니다. 즉 연구를 수행함에 있어서 연구자 주입한 어린이에 대한 편향과 모델이 생각하는 어린에 대한 인식을 구분하지 못하게 되므로, 연령과 성별만 이라는 최소한의 페르소나만 남겼습니다.

## 평가요소

| 평가요소 | 정의 (프롬프트 원문) |
|----------|-----------|
| 안전성 | 사진에 나타난 공간에서 이용자가 느낄 수 있는 안전감과 환경에 대한 신뢰의 정도. 표면, 높이가 있는 곳과 그 아래 바닥, 시설의 구조와 견고함, 공원과 차도의 관계처럼 사진에서 볼 수 있는 것을 이용자가 다칠 가능성과 관련지어 판단한다. 시설이나 바닥이 부서지거나 닳은 것은 그 때문에 다칠 수 있을 때만 안전성에서 고려한다. |
| 개방성 | 공간이 나무와 풀, 놀이시설, 담장이나 건물에 둘러싸이지 않고 열려 있는 정도. 공간 안과 주변을 이어서 내다볼 수 있는지, 시선이 무엇에 얼마나 가려지는지를 기준으로 판단한다. 빈 공간이 넓다는 것은 시선이 그만큼 멀리 보인다는 뜻으로 고려한다. |
| 심미성 | 공원의 나무와 풀, 놀이시설, 바닥의 색, 모양, 재료, 배치가 어우러져 보기에 얼마나 좋은가. 눈길을 끄는지, 흥미로운지, 디자인 의도가 느껴지는지, 요소들이 서로 어울리는지를 기준으로 판단한다. 시설의 보이는 모습이 아름다운지를 고려한다. |
| 다양성 | 공원에 얼마나 여러 가지 것이 갖추어져 있는가. 시설의 종류, 평탄한 곳과 높낮이가 있는 곳, 넓은 곳과 좁은 곳처럼 서로 다른 공간의 종류, 바닥 재료의 종류, 식생의 종류를 보고 그 가짓수와 폭을 판단한다. 같은 종류가 여러 개 있는 것보다 서로 다른 종류가 있는 것을 높게 본다. |
| 관리성 | 공원이 지금 얼마나 잘 관리되고 있는가. 나무와 풀이 건강하게 자라고 다듬어져 있는지, 놀이시설·벤치·바닥이 부서지거나 닳거나 벗겨지지 않았는지, 쓰레기나 낙서 없이 깨끗하고 정돈되어 있는지, 시설과 식재가 제자리에 질서 있게 놓여 있는지를 기준으로 판단한다. |
| 놀이성 | 공원의 시설과 공간이 이용자의 놀이를 얼마나 여러 유형으로, 얼마나 깊이 지원하는가. 구성놀이, 기능놀이, 상상놀이, 사회놀이, 규칙이 있는 놀이가 각각 가능한지와, 신체적 도전과 감각적 자극의 기회가 있는지를 기준으로 판단한다. 그곳에서 놀이가 실제로 일어날 수 있는지를 고려한다. |
| 사회성 | 공원의 공간 구성이 이용자들이 만나고 함께 있을 수 있게 얼마나 지원하는가. 몇 명이 머물며 어울릴 수 있는 자리와 여럿이 모여 함께 활동할 수 있는 공간이 있는지, 그런 자리들이 서로 이어져 있는지를 기준으로 판단한다. |
| 종합성 | 사진에 나타난 공원을 하나의 장소로 보았을 때 전체적으로 얼마나 좋은 공원인가. 앞에서 살펴본 모든 면을 함께 떠올리되 점수를 더하거나 평균하지 않고, 이 공원이 전체로서 이용자에게 어떤 곳인지 전반적으로 판단한다. |

여섯 요소(안전성, 개방성, 심미성, 다양성, 관리성, 종합성)는 MLLM으로 서울 가로 녹지를 평가한 이다겸 외(2025)에서 가져왔습니다. 다만 원래 식물종의 다양성이던 다양성은 어린이공원에 맞게 시설과 공간의 다양성으로 바꿨습니다. 어린이공원은 결국 노는 곳이고 친구와 어울리는 곳이라고 생각해서 **놀이성**과 **사회성**을 더했습니다. 놀이성은 영국 놀이공간 10곳의 놀이가치를 평가한 Woolley & Lowe(2013)의 놀이 유형 5종과 도전·자극 항목에서, 사회성은 사회성을 "모이고 상호작용하기에 유리한 조건"으로 정의한 Agarwal et al.(2021)에서 가져왔습니다.

## 대상지

**인천광역시 미추홀구 어린이공원 53개소 전체**

미추홀구는 저층 주거지가 밀집한 구도심으로, 1인당 공원 면적이 하위권입니다. 한편 재개발이 활발하게 진행되면서 어린이공원의 준공연도가 1980년부터 2025년까지 고르게 퍼져 있습니다. 오래된 공원과 새 공원이 한 구 안에 함께 있어, 같은 기준으로 비교하기에 알맞다고 생각했습니다.

## 레포지토리 내용

### 폴더 구조

```
experiment/
  config.yaml        # 실행 설정 (모델, 페르소나, 반복 수, 경로)
  prompts/           # 시스템 지시, 요청문, 페르소나 7종, 방향별 사진 안내
  src/               # 실행 코드
  results/           # 실행 결과 (calls.jsonl, scores.csv)
  analysis/          # 정량 분석 코드와 결과
```

### 주요 파일

`experiment/src/run.py`는 실행 진입점입니다. 공원마다 사진 4장을 모델에 올리고, 7개 조건을 5회씩 평가해 결과를 저장합니다. 

`experiment/prompts/system.md`는 평가 절차, 근거 작성 규칙, 촬영 방향 인용 형식, 8개 평가요소의 기준을 담은 시스템 지시입니다. 페르소나는 `prompts/personas/`의 한 줄짜리 파일로 따로 붙입니다.

`experiment/analysis/quant.py`는 기술통계, 대응표본 t검정, 반복 일관성, 방향 인용 빈도를 계산하고, `correction.py`는 요소별 Bonferroni 보정(가설 1 p<0.0083, 가설 2 p<0.0033)을 적용합니다.

`.env.example`은 API 키 템플릿입니다. 재현하실 때는 `.env`로 복사한 뒤 Gemini API(Google AI Studio 혹은 VertexAI에 있음) 키를 넣으면 됩니다.

### 시스템 산출물 구조

`results/calls.jsonl`에는 호출마다 요청 설정, 토큰 사용량, 모델 응답 원문이 한 줄씩 저장됩니다. `results/scores.csv`는 이를 공원 × 조건 × 반복 × 평가요소 단위로 풀어 점수와 근거 문장을 담은 표입니다. 정량 분석은 `scores.csv`로 진행하였습니다.

### Model 설정값

- 모델: gemini-3.8-flash (thinking effort: low, temperature: 1.0)
- 이미지 해상도 ultra_high

(모델, 이미지, 반복 설정은 필요하시면 `experiment/config.yaml`에서 직접 변경 가능합니다)

### 분석 재현

```bash
pip install -r experiment/requirements.txt
python experiment/analysis/quant.py --config experiment/config.yaml
python experiment/analysis/correction.py
```
